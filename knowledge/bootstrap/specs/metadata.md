# KOS Metadata — frontmatter, Purpose header, the seven types

> Read when creating or editing any note. Infrastructure files (`index.md`,
> `PROJECT.md`) are exempt from this spec (`architecture.md` §3).

## 1. Note anatomy

Every note = YAML frontmatter + Purpose header + body (+ generated Backlinks footer):

```markdown
---
type: lesson
status: stable
created: 2026-07-04
updated: 2026-07-04
related: [../patterns/hook-structure.md]
depends_on: []
---

# <Title>

**Purpose:** this file exists to explain <X>.
**When to read:** read this when <situation>.
**Do not duplicate:** if writing about <X>, extend this file instead of creating a new one.

<body…>

## Backlinks
<!-- AUTO-GENERATED by knowledge-lint --fix. Do not edit. -->
```

## 2. Frontmatter schema (authoritative — `knowledge-lint` validates against this)

```json
{
  "type": "object",
  "required": ["type", "status", "created", "updated"],
  "additionalProperties": false,
  "properties": {
    "type": { "enum": ["concept", "pattern", "decision", "lesson", "experiment", "research", "glossary"] },
    "status": { "enum": ["draft", "stable", "canonical", "deprecated"] },
    "created": { "type": "string", "format": "date" },
    "updated": { "type": "string", "format": "date" },
    "related": { "type": "array", "items": { "type": "string" } },
    "depends_on": { "type": "array", "items": { "type": "string" } },
    "superseded_by": { "type": "string" }
  }
}
```

Field rules:

- **Dates are absolute ISO** (`YYYY-MM-DD`), never relative. `updated` changes on every
  substantive edit (not on `--fix` regeneration).
- **`related`** — sideways edges: notes/files a reader of this note should know exist.
- **`depends_on`** — upstream edges: knowledge this note *builds on*; if the upstream
  changes, this note may be stale.
- Both hold **relative markdown paths** from this file (`linking.md`). Empty/omitted is
  legal — never add filler edges.
- **`used_by` does not exist.** Backlinks are generated into the footer by
  `knowledge-lint --fix`; hand-written inverse links rot.
- **`superseded_by`** — only on `status: deprecated` files: relative path to the
  successor (`lifecycle.md`).

## 3. The Purpose header (three mandatory lines)

Sits directly under the H1, for a reader deciding whether to read on — and against
duplication:

- **Purpose:** what this file exists to explain (one line).
- **When to read:** the situation that should bring a reader here (one line).
- **Do not duplicate:** "if writing about <this topic>, extend this file instead of
  creating a new one" — names the topic this file *owns*.

## 4. The seven types (one primary type per file)

| `type` | It answers | Example title |
|--------|-----------|---------------|
| `concept` | what is X? | "Forced alignment (audio↔text)" |
| `pattern` | how do we reliably do X? | "Hook scenes mirror the viewer's feed" |
| `decision` | why did we choose X? | "Render engine: hybrid Remotion+HyperFrames" |
| `lesson` | what did we learn from what happened? | "2026-06-28 — title-card scenes get rejected" |
| `experiment` | what did we try, and what happened? | "Thumbnail A/B: face vs no-face" |
| `research` | what do external sources say? | "YouTube 2026 monetization policy changes" |
| `glossary` | what does this term mean here? | "CTR" |

Type-specific body rules:

- **`lesson`** — file `lessons/YYYY-MM-DD-<slug>.md` (date = when learned). Body has
  three mandatory sections: **Finding** (one sentence) · **Evidence** (concrete: IDs,
  metrics, links) · **Decision** (what we do differently now, linked to the
  pattern/concept it updates). A lesson with no evidence stays `draft` forever.
- **`experiment`** — body states hypothesis, setup, result, conclusion. Results are
  real; a planned-but-not-run experiment is `status: draft`.
- **`research`** — every claim carries its external source and a retrieved-date.
  Unsourced research is a contradiction in terms (stays `draft`).
- **`decision`** — only in projects with no external ADR log (`architecture.md` §4).
  Body sections: Context · Decision · Reasoning · Alternatives considered · Impact.
- **`pattern`** — must cite its evidence (≥2 independent pieces) via links to
  `lesson`/`experiment`/`research` notes (`lifecycle.md`; validator check 9 at
  `canonical`).
- **`concept` / `glossary`** — definitions; keep them short and stable. Exempt from
  evidence links (a definition needs no lesson).

Choosing a type: it's what the note **answers**, not where the content came from. An
external article that changes how we work becomes `research` (the findings) plus,
if we act on it, a `lesson` or `pattern` that cites it.
