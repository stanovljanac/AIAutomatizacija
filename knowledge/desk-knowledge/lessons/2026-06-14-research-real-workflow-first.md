# Research the real-world workflow (and stress-test the tools) before scripting

**Purpose:** this file exists to explain why how-to/ideas/demo videos start with
real-workflow research and tool reliability checks, not with writing.
**When to read:** read this when starting any how-to, ideas, or demo video — before
the brief is turned into a script.
**Do not duplicate:** if writing about pre-script workflow research or tool
reliability checks, extend this file instead of creating a new one.

## Finding

Scripting a how-to/demo before researching how the task is *really* done — and before
stress-testing the chosen tool's reliability — produces demos that break and framings
that miss the tools people actually use.

## Evidence

- **2026-06 — video 008 (receipt → spreadsheet demo)**: the demo was built on Gemini's
  free tier, which returned **503s under load** when exercised at demo time — the
  walkthrough could not be trusted live and had to be reworked around a modular tool
  choice ([008 work log, PROGRESS 2026-06-14](../../../docs/PROGRESS.md); graduated
  from agent auto-memory 2026-07-04).
- The fix was systemic, not one-off: `script-writing` gained a mandatory **Step 0**
  (research the real workflow + name the real tools/competitors; keep the tool
  modular, the workflow the focus) — see
  [script-writing SKILL.md](../../../.claude/skills/script-writing/SKILL.md) — and
  CLAUDE.md operating principle 2 now points at it.

## Decision

Before scripting any how-to/ideas/demo video: (1) research how practitioners actually
do the task today and which tools/competitors they use; (2) stress-test the tool the
demo will lean on (free-tier limits, rate limits, outages) **before** committing the
script to it; (3) keep the tool modular — the workflow is the star. The rule lives
canonically in [script-writing Step 0](../../../.claude/skills/script-writing/SKILL.md);
proof scenes built on the researched workflow must still satisfy the
[visible-proof lesson](2026-06-27-proof-must-be-visible.md).
