# A TTS rate string is a request, not a pace — measure the pace you promise

**Purpose:** this file exists so that "make it 10% slower" is delivered as a measured 10%, not as a
rate string that happened to read like one — and so the two edge-tts traps behind it are not
rediscovered.
**When to read:** read before changing `brief.voice_rate` / `voice_rate_key`, before splitting a
narration into more synthesis segments (pauses, key takes), and whenever an owner asks for a pace
change in percent.
**Do not duplicate:** if writing about narration pace, key takes or segment boundaries, extend this
file; the mechanics live in `.claude/skills/voice-synthesis/SKILL.md`.


## Finding

1. **edge-tts is not repeatable run to run.** The same 5-sentence text at `-6%` came back at 20.878s
   of speech once and 20.106s the next time (3.7% apart); `+3%` happened to be stable. And the rate
   scale is not monotonic in practice: one `-6%` run was SLOWER than `-7%`. A rate string therefore
   cannot be converted to "N% slower" by arithmetic.
2. **edge-tts pads a short request to ~1.87s.** "Not one had moved." is 0.73-0.86s of speech and came
   back as 1.872s of audio — ~1s of trailing silence. Synthesising a key take as its own segment (the
   only way to give it its own rate) silently adds a pause after it that nobody asked for.

## Evidence

024 Short, 2026-10-09 (`content/024-frozen/short/`): calibration runs in the session scratchpad;
the shipped measurement is `pace.json`, made by `content/024-frozen/render/short_pace.py` — the
Short's exact sentences re-synthesised at the long cut's rate (`+3%`, one segment, mean of 3 runs)
and compared sentence by sentence, first word to last word (pauses excluded): normal lines
**1.0995x** (target 1.10), key takes **1.166x** (target 1.155).

## Rule

- When a pace target matters, **measure it**: speech time per sentence (first word start → last word
  end) against a reference synthesis of the SAME text at the reference rate. Report the measured ratio,
  not the rate string.
- A segment that ends only because the RATE changes must be trimmed back to an ordinary sentence break
  (`RATE_BOUNDARY_TAIL` = 0.30s after its last word + the next segment's ~0.1s lead-in ≈ the 0.39s
  median break measured on 024's long track). Only ever drop TRAILING mp3 frames (bit reservoir).
- Keep key takes rare (≤1 per scene); each one is a segment boundary, and every boundary is a place
  the prosody can reset.
