# A shared asset library whose files are git-ignored must be generated, not acquired

**Purpose:** this file exists to explain why the D-063 sound-design cues are synthesized by
`scripts/make-sfx.mjs` instead of downloaded from a CC0 catalogue.
**When to read:** read this before acquiring any reusable binary asset the repo is supposed to
share across videos — sound effects, beds, textures, fonts, lower-third graphics.
**Do not duplicate:** if writing about reproducibility of shared binary assets, extend this file.

## Finding

The repo git-ignores media everywhere (`*.mp3`, `*.wav`, `*.png` … — the rule that keeps it small).
A shared library is, by definition, the one place where that rule bites differently from
`content/<id>/`: a per-video render is *supposed* to be reproducible from its inputs and thrown
away, but `assets/sfx/` is an **input**. An acquired file there is untracked state on one machine.
It survives no clone, no reinstall, and no second contributor — and the video that references it by
filename fails soft, so the loss shows up as a render that quietly has no sound design, not as an
error. That is the
[fail-soft-becomes-fail-silent](2026-07-25-self-healing-passes-skip-not-abort.md) trap in asset form:
the posture that keeps a render alive is also what hides the missing input.

Writing the *recipe* instead of the *result* dissolves the problem: the generator is source, so git
tracks it, and the asset is one command away on any machine. It also settles a question the CC0 rule
existed to manage — a sound we authored has no licence, no attribution, and no strike risk on a
monetized channel.

## Evidence

- **2026-07-25 (D-063):** the sound layer + scripted-pause capabilities shipped with `assets/sfx/`
  empty and a README pointing at freesound / pixabay / mixkit. The asset step was left open, and 016
  could not use the layer it was built for.
- **2026-08-15:** `git check-ignore -v assets/sfx/riser.mp3` → `.gitignore:82:*.mp3`. Downloading
  three files would have produced a library that only ever existed in one working copy.
- The three cues the hero shot needs are all *formulas*: an exponential pitch sweep with a rising
  envelope (riser), a pitch-dropping sub plus a noise transient (impact), a stack of fast-decaying
  partials (accent). `ffmpeg`'s `aevalsrc` expresses each as one arithmetic expression over `t`, and
  ffmpeg is already vendored at `templates/hyperframes/.bin` (the same binary `make_voice.py` splices
  silence with). Verified by measurement, not by ear alone: the riser climbs −50 → −24 → −13.5 dB
  across its rise and resolves to −20.8 dB in its tail; nothing clips (peaks −3.0 / −1.1 / −2.8 dBFS).

## Decision

Reusable assets are **generated by a tracked script** whenever the format allows it; acquisition is
the fallback, not the default. `generateCue` never overwrites an existing file without `--force`, so
an owner-supplied CC0 file dropped in under the same name wins and survives every later regeneration
— the library stays swappable. The general rule: **if the repo won't track it, track what makes it.**
