# A 1:1 word→event walk desyncs the whole track the first time our tokenizer disagrees with the TTS

**Purpose:** this file exists to explain why `make_voice.py` expands a WordBoundary event into
one slot per token (`expand_boundaries`) before mapping words to timestamps.
**When to read:** read this before changing anything in the alignment path — the tokenizer, the
matcher, the pause splicing — or when a render is subtly late from some point onward.
**Do not duplicate:** if writing about TTS/alignment drift, extend this file.

## Finding

Our alignment is a **strict sequential 1:1 walk**: token *i* of the script is given the timing of
event *i* from the TTS. That is only correct while both sides agree on what a word is. The moment
our tokenizer emits one more token than the voice emits events, **every timestamp after that point
shifts by one word — for the rest of the video**, and nothing reports it. The output is a
schema-valid `alignment.json` with a slowly-wrong clock: captions land early, scene reveals fire on
the wrong beat, and a spliced silence appears somewhere it wasn't authored.

The drift is worst exactly where it matters most: it accumulates toward the *end* of the track,
which is where the takeaway and the CTA live. And it hides in plain sight, because the failure is
not a missing timestamp — the hard gate ("every sentence must have a timestamp") passes.

## Evidence

- **2026-08-15, 021 (`what-is-a-token`), first voice pass.** The D-063 scripted pause authored after
  "Not: a token is a small word" rendered as a 1.42s hole *mid-sentence*, between "token" and "is",
  while the sentence boundary itself showed a 0.00s gap. The scene most affected was s22 — the
  takeaway monolith, the one frame the video is built to be screenshotted at.
- **Measured cause** (edge-tts 7.2.8, `en-US-AndrewMultilingualNeural`): edge-tts emits a hyphenated
  compound as a SINGLE WordBoundary. Synthesizing "…twenty-one … seventy-five percent …
  character-exact … dumbest-looking…" returned events `twenty-one | seventy-five |
  character-exact | dumbest-looking` — one each. `tokens_of` deliberately splits on hyphens ("a
  hyphenated compound is spoken as separate words"), so it wanted two tokens for each. 021's script
  has five such compounds; by s22 the walk was two events behind.
- The comment in `tokens_of` asserting that splitting "keeps alignment from drifting (v2-1)" was
  simply **false for this voice/version** — and had been silently costing sync on every script with
  a hyphen since it was written.
- The matcher's apparent resync (`while … if norm(wbs[scan].w) === tok || scan === j`) is dead code:
  the `scan === j` arm matches unconditionally on the first candidate, so a mismatch can never
  trigger a scan-forward.

## Decision

`expand_boundaries()` splits a compound event into one slot per token, sharing the event's span
proportionally to part length, with the **last part keeping the event's exact end** so the track
clock cannot drift by rounding. It runs once, right after synthesis, before the 1:1 walk — so the
walk's precondition (one event per token) is *established* rather than assumed. Three tests in
`scripts/make_voice.test.mjs` pin the behaviour, including a regression that asserts
`len(expand_boundaries(events)) == len(tokens_of(sentence))` on the real 021 line.

General rule: **when two systems must agree on a count, make one of them derive the count from the
other — never trust that they agree.** And when checking a new voice track, don't only ask "does
every sentence have a timestamp?"; ask "does the LAST scene's timing still match the audio?" — drift
is invisible at the top of a track and obvious at the bottom.
