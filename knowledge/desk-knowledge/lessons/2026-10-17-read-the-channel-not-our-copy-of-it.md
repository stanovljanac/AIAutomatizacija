# A loop that waits for a hand-typed id never runs — read the channel, not our copy of it

**Purpose:** this file exists so that no future loop (analytics, distribution, learning) depends on a
human copying a fact from YouTube into our files — that is the step that silently never happens.
**When to read:** read before building anything that needs to know what is live on the channel
(ids, titles, playlists, numbers), and before trusting a field in `publish.json` that only an upload
would fill.
**Do not duplicate:** the mechanics live in `docs/ARCHITECTURE.md` §12 (growth loop) and D-073; extend
this file with new cases of the same trap.


## Finding

1. **The analytics loop was built, tested and never ran.** It learned a video's YouTube id only from
   `publish.json.youtube_video_id`, which the API upload used to write. When uploads became manual
   (D-055) nobody typed the id back, so after five months **0 of 68 ideas had metrics, no snapshot
   existed, and 4 of 17 ledger records had an id.** Every test was green the whole time — the tests fed
   the loop ids; reality never did.
2. **Our copy of a video's identity is not its identity on YouTube.** The owner renames at upload
   (025: "AI Agents Make Mistakes…" locally, "This is how my AI Agent Sent 73 Emails Nobody Approved"
   live), two Shorts can come out of one folder (007), and one video we think is published was never
   uploaded (020's Short). Only the channel knows.
3. **"Available in the API" needs a live probe.** The Analytics API knows the metric name
   `videoThumbnailImpressions` but refuses it in every query shape; `video×creatorContentType` is
   refused as a dimension pair; impressions exist only as a Reporting API bulk report whose files
   expire after 30–60 days, and that API must be enabled separately in the Cloud project.

## Evidence

2026-10-17, read-only probes against the live channel (scripts in `F:\AI\.tmp\quadrant1\`): 33 uploads
listed from the Data API vs 18 ledger records; title matching tied 22 automatically, 11 needed a
hand mapping; after the rewired run the ledger had ids on 17 of 18 records and 8 ideas had metrics.
The Reporting API answered "has not been used in project … or it is disabled".

## Decision

- Anything that needs live facts **lists them from YouTube** (the channel catalog,
  `pipeline/state/youtube.json`) and ties them to our folders — automatically only when certain,
  otherwise it asks (`--map`), because a wrong tie puts one video's numbers on another idea.
- Keep what YouTube will delete (reach rows) in our own state; never assume a report can be re-fetched.
- A loop's test suite must include one run against the real source, or a green suite proves nothing
  about whether the loop ever gets input.
