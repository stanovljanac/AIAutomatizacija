# An agent experiment leaks whatever the agent can read — hide the answer behind a real interface

**Purpose:** this file exists so that the measured experiments behind our videos (025's 30 unattended
runs, 026's 99) measure the agent's behaviour, not a shortcut the test harness handed it.
**When to read:** read before building any sandbox a headless agent (Claude Code CLI `-p`, or any
other) is pointed at to produce a number we will say on screen.
**Do not duplicate:** each video's harness lives in its own `content/<id>/measure/` (git-ignored);
this note holds only what transfers between them.


## Finding

1. **The agent reads the tool's source.** In 026's second pilot the form "connector" was a script that
   printed a fixed answer per condition. Given a shell, the agent opened it, saw `submissions: []`
   hard-coded, and reported "the tool is a stub" — a catch no real agent could make against a real
   API. The result would have overstated how often an agent notices an empty source.
2. **The CLI tells the agent the real date.** The harness prompt said "Today is Tuesday 13 October";
   the CLI's own environment header said 18 October. Agents hedged ("I also checked Friday 17th as a
   fallback"), queried extra dates and wrote about the discrepancy — noise in exactly the behaviour
   being measured (which dates it checks). 025 had the same mismatch (12 vs 10 October) and lived with it.
3. **Agents put the output where they like.** Reports landed in `report.md`, `reports/report.md`,
   `reports/<date>.md`, and once one folder *above* the sandbox. A scorer that looks in one place
   reports "no report" for a run that did the job.
4. **Keyword scoring misfires on clean reports.** "exit 0, no errors" matched an `error` alarm rule
   and turned two healthy-day runs into false alarms until every report was read by hand.

## Evidence

026 `measure/` (2026-10-18): pilot 2 reports quoting the stub's source; pilot 1/2 `_run.json` results
discussing the two dates; the stray report at `F:/AI/.tmp/proof-stale-haiku-4/report.md`; the two
`proof-ok-haiku-*` false alarms traced to "no errors". After the fixes, 99 runs scored (12 more aborted on a subscription limit) and then
re-read report by hand: no verdict changed except those two (both corrected to "correct").

## Decision

- **The answer lives behind an interface the agent cannot open:** a local server (026: `batch.mjs`
  plays the form's API, one random token per run → its state); the sandbox holds only an ordinary
  client. Past dates answer like a real store would, so a cross-check is a real cross-check.
- **The scenario's "today" is the run's real date** (computed at build time), never a second date.
- **Collect every file the run created** (diff of the sandbox before/after, plus a look one level up),
  not one expected path; log every request the agent made, so "did it check another day" is measured.
- **Keyword rules are a first pass only;** every verdict that becomes a spoken number is read by hand,
  and the corrections are kept in the scorer (`MANUAL`), not in a note.
