# A 3D test clip is not a scene — four things that must change before it can carry a beat

**Purpose:** the `t3d-*` Three.js tests looked good in isolation and were wrong in every way that
matters the moment they had to hold a slot in a real video. This file is the list, so the next 3D
scene is authored as a scene from the first line.
**When to read:** before authoring or promoting ANY Three.js (`HF3`) scene, and whenever a 3D clip
"looks lower quality than the 2D ones" without an obvious cause.
**Do not duplicate:** if writing about 3D scenes, depth-of-field, or 3D typography, extend this file.

## Finding

Three test clips (hook / window / pile) were built at a fixed 210 frames to prove the Three.js
adapter worked. Retiming them into 11.6s, 18.4s, 11.4s and 11.0s slots exposed four separate
defects, none of which the test length could reveal.

**1. Absolute seconds do not survive a slot change.** The tests hung every action off literal
numbers (`appear = 0.15 + i*0.031`, `rs = 1.85, re = 4.15`); only the camera orbit used `t / D`.
Stretch the duration and the shot finishes in four seconds and then orbits an inert object for
fourteen. A 3D scene has to derive every mark from `S.beatAt(...)` exactly like a 2D one — the
sentence the action belongs under is the only correct clock.

**2. A label that writes no depth is blurred by the wall behind it.** This one cost a render and is
completely non-obvious. `HF3.composite` gets its depth-of-field from the DEPTH BUFFER, so a text
plane built with `transparent: true, depthWrite: false` (the reflex for unlit overlay geometry)
leaves the depth of whatever is *behind* it — a back wall sixteen units away — and the shader blurs
those pixels to the maximum circle of confusion. Every word in the frame came out smeared while the
paper beside it was pin-sharp, which reads as "3D looks cheap" rather than as a bug. The fix is
`depthWrite: true` + `alphaTest`, so the transparent margin is discarded instead of hidden, and only
the ink writes depth. **The same trap applies to any transparent backdrop**: the window scene's dark
glass pane had to start writing depth too, or the empty part of the frame focused on the wall.

**3. A message is not a sheet of paper — thin it on the way down.** The hook's 16 chat panels are
0.16 units thick, and folding them flat at 0.2 pitch landed a stack that read as venetian blinds.
Paper needs pitch ≈ thickness: scale the panel's thickness to ~0.34 as it folds and land it at 0.062
pitch. Same failure in the pile scene at 0.105 pitch, which read as shelves rather than a stack.

**4. The object must be staged for the shot it is IN, not for the shot it ends in.** The window
scene's pile sits alone inside a large gold frame for seven seconds before it redistributes, and at
its final row scale it was a 20%-wide chip in an empty rectangle. It is staged at 1.75× while it is
one pile and lerps to 1 as it stands up into four groups — which reads as the paper being divided
into smaller shares, i.e. the sentence.

## What to do

- Derive every 3D mark from the beats; `t / D` is for the camera, never for the action.
- `HF3.textPlane` is the primitive for words that belong to an object (labels, token capsules). Lines
  that install a claim stay flat DOM in the house typography — a kicker must never sit in perspective.
- Never set `depthWrite: false` on anything the depth-of-field is supposed to focus. Use `alphaTest`.
- Give a 3D scene the same props contract as its 2D twin, so swapping the takes is one field
  (`props.hf_scene`) and the owner can judge them inside a full render instead of as isolated clips.
- Judge a 3D clip on extracted frames at its REAL slot length, never on the 7-second test.
