# A free-tier external reviewer becomes a single point of failure once review volume outgrows its quota

**Purpose:** this file exists to explain why the review panel no longer depends on a
free-tier external API in its critical path (D-053).
**When to read:** read this when configuring reviewers/providers, or when tempted to put
any free-tier external API inside a loop whose call volume grows with the system.
**Do not duplicate:** if writing about reviewer-provider reliability or free-tier quotas
in the review loop, extend this file instead of creating a new one.

## Finding

A free-tier external reviewer works while the system is small, but the review loop's call
volume scales with the system (stages × iterations × videos) — once it crosses the
provider's daily quota, the reviewer becomes a production blocker: it stalls the loop
mid-video and its own retries consume the remaining quota.

## Evidence

- **2026-07-09, video 012 script review:** `gemini-3.5-flash` returned sustained 503
  ("high demand") across the whole day; the one response that landed mid-window was
  malformed JSON; backoff retries then exhausted the free-tier daily cap → 429
  RESOURCE_EXHAUSTED (`GenerateRequestsPerDayPerProjectPerModel-FreeTier`, limit 20/day)
  ([012 log](../../../content/012-studio-reveal/log.md)).
- Precedent: **008** built a demo on Gemini's free tier and hit 503s at demo time —
  [research the real workflow first](2026-06-14-research-real-workflow-first.md). Same
  failure class, now in our own tooling rather than a demo.

## Decision

**D-053** (docs/DECISIONS.md): Gemini retired from the review panel by owner decision —
`enabled: false` in config (kept for provenance); the panel gates with a **single Claude
sub-agent** (orchestrator guard skips review only when the panel is empty; pinned by
`pipeline/shared/review/panel-config.test.mjs`). General rule this teaches: **never place
a free-tier external API in the critical path of a loop whose call volume scales with
system growth** — stress-test the quota math the same way 008 taught us to stress-test
demo tools.
